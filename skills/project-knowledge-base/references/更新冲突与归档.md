# 更新、冲突与归档

## Enter update mode

Read `knowledge-base.yaml`, the root README, AI collaboration rules, CURRENT, the current task package, and only then its linked features, contracts, ADRs, Profiles, acceptance rows, and evidence. Do not reinitialize an existing target or infer current requirements from archives.

Use the Proposal and explicit-confirmation contract for every formal baseline change.

## Preserve versions

For an approved replacement:

1. Create the new item with a new version, sources, confirmer, and confirmation time.
2. Add `supersedes: [OLD-ID]` to the new item.
3. Set the old item to `superseded` and add `superseded_by: NEW-ID`.
4. Keep the old content or move it to `90-历史归档/`; never silently delete it.

For conflicting evidence, retain each value and source, set `conflicted`, name `resolution_required_from`, and stop before choosing a winner.

## Change Profiles additively

Adding a Profile requires confirmation, its descriptor, additive templates, newly discovered knowledge gaps, and validation. Reject core field/status, authority-path, approval-rule, or acceptance-result overrides.

Removing a Profile removes its ID from the active `profiles` list and stops its mandatory checks. Keep its descriptor, generated knowledge, approval history, and evidence as historical material. Do not delete knowledge merely because the Profile is no longer active.

## Sensitive information

Store configuration locations and `${ENV_VAR}` names, never values. Redact personal data. Preserve only the minimal external excerpt and a versioned reference needed for traceability.
