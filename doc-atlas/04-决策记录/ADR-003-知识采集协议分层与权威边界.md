# ADR-003：知识采集协议分层与权威边界

## 背景

知识采集规则同时出现在项目知识库、插件 `references/` 和目标知识库模板中。三者分别服务于产品治理、Agent 执行和产物自包含，但如果都被当作完整协议，就会形成多权威源和规则漂移。

## 备选方案

1. 将完整协议全部内联到每个 `SKILL.md`。
2. 只在目标知识库中保存协议，Skill 读取项目文件执行。
3. 建立“产品执行协议—薄 Skill—持久化协作说明—确定性约束”分层。

## 决策

选择方案 3：

- `references/` 是知识采集完整执行协议的唯一规范源。
- `skills/*/SKILL.md` 是薄执行适配器，只保留触发、协议加载、编排和终止条件。
- 目标知识库的 `05-知识治理/AI知识采集协议.md` 保留持久治理语义，并作为无 Skill 时的最低兼容入口，不复制插件的运行时细节。
- Schema 是机器结构权威，执行器和检查器实施确认门禁、受控写入和结构验证。

## 影响

- init、update 以及未来新增 Skill 可共用同一套执行协议。
- 目标知识库在插件卸载或更换 Agent 后仍可被理解和人工维护。
- 模板不承载插件命令、运行时探测和平台适配细节，降低升级漂移。
- 自动化测试必须验证 Skill 引用规范源、模板声明轻量边界，以及发布资产与源文件同步。

## 边界修订

2026-08-19 用户进一步确认：Context Atlas 只负责知识沉淀和读取，不负责项目如何开发。因此格式 3 将该目录改为 `05-知识治理`，不再生成“本地开发”和“测试规则”文档。旧文件中有实质项目内容时，迁移必须停止并请用户决定其归属，不得静默删除。

## 回滚条件

只有当多个受支持 Agent 无法稳定加载共享协议，且已有跨 Agent 证据证明薄适配层不可行时，才考虑在各 Skill 中内联必要的最小规则子集；`references/` 仍保留为语义源。
