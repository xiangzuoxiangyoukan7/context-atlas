# ADR-005：规格事实基线与变更工作区分层

## 背景

Context Atlas 已能治理来源、确认、关系、影响和证据，但现有需求、功能、接口、模块和验收模板的规格强度不一致。开发者能够理解总体意图，AI 在输入输出、状态、异常、非功能约束和验收场景不足时仍可能补写未批准事实。Spec Kit 擅长澄清、质量门和任务拆分，OpenSpec 擅长当前规格、变更增量和归档合并；直接复制任一目录会与 Context Atlas 当前事实权威和确认门禁重叠。

## 备选方案

1. 保持现有模板，仅通过更强提示词要求 AI 自行理解。
2. 把 Spec Kit 或 OpenSpec 目录作为 Context Atlas 的新权威结构。
3. 保留 Context Atlas 为长期事实层，吸收 Spec Kit 的规格质量门和 OpenSpec 的变更 Delta，并以只读适配器连接外部工作流。

## 决策

本决策中“验收契约必须独立建模”的部分自 2026-08-30 起由 `ADR-010` 替代；功能自身设计、独立契约和验收场景分层的部分自 2026-08-31 起由 `ADR-011` 替代。其余规格事实基线与变更工作区分层决策继续有效。

选择方案 3：

- Context Atlas 保存当前批准且有效的需求、功能、架构、契约、约束、验收场景和证据关系。
- OpenSpec、Spec Kit、Issue 和其他 Agent 工作流保存单次变化、设计和任务；其状态不是正式知识批准。
- 需求与功能回答 `WHAT/WHY`，架构与设计回答 `HOW`，任务描述执行步骤，验收证据记录实际结果。
- 批准状态、生命周期状态和规格就绪度独立建模；批准或当前有效不自动代表可以开发。
- 变更使用 `ADDED`、`MODIFIED`、`REMOVED`、`RENAMED`、`SUPERSEDED`；合并当前基线必须重新经过 Context Atlas 的精确 Proposal 确认。
- 验收场景、验收结果和验收证据保持可追溯，具体存储粒度由后续 `ADR-010` 调整。
- 确定性检查器增加规格覆盖、就绪度、Delta 和跨文档一致性规则；语义审查由一个只读 `context-atlas-review` Skill 承担，不按文档类型继续拆分多个 Skill。
- 先实现 OpenSpec 适配，再实现 Spec Kit 适配；二者默认只读并保留原始来源。
- 新模板和 Schema 用于新项目；旧知识库通过格式升级和首次修订渐进迁移。

## 影响

- F04 和 F05 增加新的产品要求与验收项；当前已通过的旧验收不自动覆盖新增能力。
- 需求、功能、模块、接口、架构、变更和验收模板需要分阶段升级。
- Schema、关系目录、检查器、黄金样例、升级器和跨 Agent 验收需要同步实现。
- 新增只读审查 Skill 不改变 `add`、`revise`、`retire` 的正式写入边界。
- Context Atlas 不接管外部任务调度，也不因规格未就绪而撤销用户给予其他工具的执行许可。

## 回滚条件

若跨 Agent 实证表明当前事实层与外部变更层无法通过稳定 ID 和来源关系可靠映射，可重新评估适配边界；任何改为共享权威目录或自动合并的方案都必须形成新 ADR，不得绕过 Proposal 确认。
