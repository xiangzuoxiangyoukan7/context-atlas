# ADR-010：知识粒度与验收场景归属

## 背景

`doc-landRightsSurvey` 的宗地图新增需求实证表明，聚合接口文件无法被其他功能精确复用，只有稳定编号的文件名不能表达用途；另一方面，把每个短验收场景和单功能局部约束拆成独立文件造成导航碎片，独立维护收益不足。

## 决策

- 一个具体端点、事件或交换入口一个接口文件，文件名和标题必须包含业务用途。
- 总路由、Servlet 集合和集成概况进入系统架构或外部依赖，不建立伪接口。
- 业务验收标准写在需求文件，具体验收场景以稳定 `AC-*` 编号内嵌在功能文件。
- 验收结果、证据和矩阵继续独立维护并关联场景编号。
- 独立契约必须声明多方复用、跨边界、独立版本、独立责任方或脱离单一功能继续有效的依据；局部约束回归所属知识文件。
- 格式 8 及更早版本的 `acceptance_contract` 保持可读；格式升级只更新表达能力，不自动合并业务正文。

## 影响

- 新知识库不再生成 `03-变更与证据/验收契约/`。
- 检查器改为验证功能声明的场景编号与内嵌场景完全一致，并要求 GIVEN、WHEN、THEN 和验证方式。
- 接口初始化与检查器拒绝无业务名称和聚合多个 HTTP 端点的接口文件。
- `ADR-005` 中验收契约必须独立建模的部分被本决策替代。
- 本决策中允许独立契约继续建档的部分自 2026-08-31 起由 `ADR-011` 替代；接口粒度和验收场景内嵌功能的决策继续有效。

## 来源

- `existing_document`：`doc-landRightsSurvey` 中 `REQ-ZDT-001`、`F-ZDT-001`、聚合接口、八个验收契约和单功能文件存储契约。

## 回滚条件

若多个真实项目证明内嵌场景无法稳定关联结果和证据，或功能文件因场景数量无法维护，可重新评估按可复用验收套件拆分；不得恢复为每个短场景默认单文件。
