# 系统架构

## 组件

1. **可安装 Skill**：让 Agent 获得初始化、采集、确认、更新和验收流程。
2. **通用协议文档**：为不支持 Skill 的 Agent 提供等价入口。
3. **核心模板**：生成与语言无关的完整知识库。
4. **技术栈知识**：在同一知识库中记录各技术的版本、目录、用途、命令和配置。
5. **Schema**：作为文档结构和状态的唯一机器规范。
6. **检查器**：读取 Schema，检查结构与追溯，不判断业务内容正确性。
7. **黄金样例**：验证单技术栈和多技术栈项目共享同一结构。
8. **数据资产**：记录重要业务数据的来源、负责人、质量、安全和保存规则，并引用数据库、接口契约和外部依赖等技术契约。

## 数据流

用户通过 Agent 发起请求。Agent 读取 Skill，检查项目和知识缺口，形成 Proposal 并向用户确认；确认后 Agent 写入 `doc-<项目名>/`，再运行检查器。知识库本身不调用模型，不提供独立用户 CLI。

## 权威边界

- 仓库事实可以由 Agent 观察，但业务含义仍可能需要用户确认。
- AI 推测只能作为假设。
- 用户确认后的知识才可成为批准基线。
- 检查通过只证明结构和追溯关系符合规则。
