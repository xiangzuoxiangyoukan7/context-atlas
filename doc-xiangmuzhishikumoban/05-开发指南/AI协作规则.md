# AI 协作规则

## 读取顺序

每个新会话按以下顺序读取：

1. 当前 Agent 已安装的项目知识库 Skill；不支持 Skill 时读取通用协议文档。
2. 项目根 `README.md`。
3. `doc-<项目名>/README.md`。
4. 本文件和 [AI 知识采集协议](./AI知识采集协议.md)。
5. `03-实施与验收/CURRENT.md`。
6. CURRENT 指向的任务包；无可执行任务时停止，不从规划或归档自行选择任务。
7. 任务包关联的功能卡、架构契约、ADR、Profile 和验收项。

目标项目可以存在 `AGENTS.md`、`CLAUDE.md` 等入口，但它们由对应 Agent 或项目维护，不属于本产品的初始化产物。

## 上下文规则

- 当前文档、功能卡、契约、ADR 和验收矩阵是不同类型的证据，不能互相替代。
- 发现冲突时列出冲突来源、版本和需要确认的问题，不自行选择“看起来合理”的内容。
- 缺少范围、边界、依赖或验收标准时先提出问题，不补写未批准事实。
- 仓库观察、用户陈述和 AI 推测必须分别标记；AI 推测只能作为待确认假设。
- 写入正式基线前先向用户展示 Proposal、来源、假设和未决问题。
- 历史归档只能提供背景，不得作为当前需求或完成状态来源。
- 自动检查通过只表示结构和引用满足规则，不表示内容已经正确批准。
- 生成计划时必须列出每项计划步骤引用的功能、设计和验收依据。
- 本 Skill 不执行代码、不替用户验收、不把 AI 输出当成项目事实。

## 初始化与维护

- 初始化默认在项目根目录创建 `doc-<当前目录名>/`。
- 目标知识库已存在时不得重新初始化或覆盖，应进入更新流程。
- 初始化和更新均由 Agent 与用户对话驱动，不依赖独立用户 CLI。
- 结构检查器只验证格式和追溯关系，不能批准内容。

## 无任务状态

当 CURRENT 明确为“无可执行开发任务”时，只允许整理、评审和更新知识库治理文档；不得启动任何业务项目实现。
