# F01：Agent 驱动的知识库初始化

## 目标

用户在项目根目录的 AI Agent 中提出初始化请求，Agent 根据可安装 Skill 创建 `doc-<项目目录名>/`。

## 规范性行为

- 根据当前目录名生成默认知识库名称。
- 允许用户明确覆盖项目名称。
- 初始化统一知识库，不选择技术栈或技术栈模板。
- 默认使用标准工作区；用户可明确选择 Obsidian 模式并获得最小 Vault 与关系图谱颜色配置。
- Obsidian 图谱按每篇正式文档的 `type` 分色；初始化与升级使用同一映射，升级只更新受管类型查询并保留用户颜色组和其他设置。
- 初始化前展示目录和首版候选内容。
- 目标存在时停止并转入更新流程。
- 根据当前宿主 Agent 创建或补充对应的 `AGENTS.md` 或 `CLAUDE.md` 入口说明。
- 初始化暂存目录只能位于项目根固定 `.context-atlas-temp/` 的操作子目录中，不在项目根散落其他临时目录。

## 功能设计

### 设计概述

初始化由 Agent 收集项目事实并展示 Proposal，确定性执行器在精确修订确认后，从同一套核心模板、Schema 和运行资产生成自包含知识库。目标已存在时停止初始化并路由到维护流程。

### 处理流程

1. 解析项目根、项目显示名称、当前宿主和 `standard | obsidian` 工作区模式。
2. 检查目标 `doc-<项目名>/` 和宿主入口文件，保留已有入口内容。
3. 展示初始化目标、候选事实、来源、未知项、关系和验证计划。
4. 在 `.context-atlas-temp/` 的操作子目录中物化模板并运行结构验证。
5. 验证通过后原子移动到目标目录，再写入或更新宿主入口的受管区块。
6. 运行目标内置 `children`、`neighbors` 和 bounded `graph` 冒烟验证。

### 输入、输出与状态变化

- 输入是项目根、可选项目名、工作区模式、宿主入口和已确认 Proposal。
- 输出是唯一的 `doc-<项目名>/`、可选最小 Obsidian 配置以及宿主入口受管区块。
- 用户确认前保持零正式写入；结构验证失败时不声明初始化成功。

### 异常、边界与降级

- 目标知识库已存在时不得覆盖、合并初始化或用模板重建。
- 无法识别宿主时不创建入口文件。
- 任一暂存、验证、原子替换或入口写入失败时回滚本次创建结果。
- 旧 `.context-atlas-tmp/` 不迁移、不删除，新操作也不得继续使用。

### 权限、安全与非功能设计

初始化不得覆盖已有知识库、已有 Obsidian 配置或入口文件的非受管内容。生成结果必须自包含，不得依赖模板仓库的私有相对路径。

### 技术对象与影响

核心模板、Schema、初始化器和宿主入口适配器共同实现本功能。标准与 Obsidian 模式共享同一正式知识结构，Obsidian 只增加本地展示配置，避免形成第二套知识模型。

### 设计取舍

采用“暂存验证后原子替换”避免目标中出现半完成知识库；宿主入口放在知识库创建成功后写入，以便入口失败时能够恢复原文件并移除本次目标。

## 排除

- 独立用户 CLI。
- 覆盖项目已有的 Agent 入口文件内容。
- 未经用户确认直接建立批准基线。

## 验收场景

- `F01-AC-01`：Agent 能生成完整、自包含的 `doc-<项目名>/`。
- `F01-AC-02`：初始化不会覆盖已有目录；若 Proposal 明确了当前宿主，则只创建或补充对应入口文件的 Context Atlas 受管区块，并保留原内容。
- `F01-AC-03`：标准和 Obsidian 初始化模式均产生可验证且不覆盖已有配置的目标；每种正式文档类型都有且仅有一个主颜色查询，升级保留用户自定义颜色组和 `workspace.json`，Obsidian 展示配置不进入正式知识治理。
- `F01-AC-04`：初始化产生的所有临时目录均位于项目根固定 `.context-atlas-temp/` 内，操作结束后清理操作子目录，且不迁移或删除旧 `.context-atlas-tmp/`。

## 关键决策与依据

- 产品采用 Agent、Skill、共享协议、模板、Schema 和确定性检查器，不提供独立用户 CLI。
- 初始化默认使用标准工作区，只有用户明确选择时生成最小 Obsidian 配置；展示配置不参与正式知识治理，已有配置不得覆盖。
- 类型颜色映射是初始化、升级和健康质检的单一事实源；`type` 查询标识 Context Atlas 受管颜色组，其他查询属于用户配置并保留。
