# 剩余知识操作实现计划

**目标：** 完成轻量格式兼容与必要转换、多人身份归属、主动知识捕获和待确认提案队列。

**共同边界：** Context Atlas 只治理知识写入，不控制开发任务；所有正式基线修改仍需同修订 Proposal 的显式确认；自动捕获只能产生 `proposed` 提案；Git 身份只用于候选匹配，不自动批准人员映射。

## Task 1：格式兼容诊断

- 建立共享 `compatibility.json`，声明可读取格式和新建格式。
- `knowledge-base.yaml` 增加默认隐藏整数 `format_version` 和业务 `project_version`。
- 只读诊断区分：直接兼容、可选等价转换、必须迁移、无法支持。
- 缺少格式版本按旧格式 1 识别，不猜测其他版本。
- 提交：`兼容：增加知识库格式诊断`。

## Task 2：必要的等价转换

- 第一条转换规则把可唯一定位的旧 `sources` 补充为 `rel_supported_by` 文件链接。
- 转换 Proposal 列出目标文件、转换项和无法唯一定位的来源；歧义时零写入。
- 只有 `proposal_revision == confirmed_revision` 才原子写入，并只更新 `format_version`，不修改 `project_version`。
- 转换后运行最新版检查器；Git 负责恢复，不另建备份系统。
- 提交：`迁移：支持旧来源关系等价转换`。

## Task 3：稳定人员身份和 Git 候选匹配

- 建立 `person` Schema、协作人员模板和邮箱 SHA-256 摘要规则。
- 读取仓库局部 Git `user.name`、`user.email`，按已确认别名匹配 `PERSON-*`。
- 未匹配、重名或自动化账号只返回候选，首次映射必须人工确认；不自动写人员表。
- 提案区分 `proposed_by`、`operated_by`、`confirmed_by` 和可选 `git_commit`。
- 提交：`协作：增加 Git 人员候选匹配`。

## Task 4：主动知识捕获和待确认队列

- 建立 `knowledge_proposal` Schema 和 `03-实施与验收/知识提案/` 模板。
- 支持用户决定、需求/规则变化、契约变化、计划前、交付前、验收后、发版前、会话结束八类检查点。
- 捕获命令接收结构化候选，按目标 ID 与内容摘要去重；只写 `proposed` 提案，不修改正式知识。
- `.superpowers/` 默认不扫描；其他插件文件只登记为来源路径，不复制全文。
- 提交：`采集：增加待确认知识提案队列`。

## Task 5：Skill、模板、样例和阶段验收

- 更新 Skill 触发规则、中文操作说明和自包含资产。
- 黄金样例展示格式版本、协作人员和待确认提案，但不虚构批准结果。
- 新增 `TASK-KB-009`～`010` 和对应验收证据。
- 运行全量测试、注释、规则覆盖、Skill 同步、三套知识库检查和差异格式检查。
- 分功能提交文档与最终验收记录。
