# 初始化产物契约

## 命名

Agent 在项目根目录初始化知识库。默认项目名取当前目录名，知识库目录为 `doc-<项目名>/`；用户可以明确覆盖项目名。

## 必需结构

初始化结果必须包含根 README、机器入口、项目总览、功能基线、架构与契约、变更与证据、决策记录、知识治理和历史归档。项目总览固定包含项目概述和术语表；功能基线包含需求与功能子目录；技术基线默认作为系统架构章节。模块、接口和独立契约必须具有明确目录并一项一文件。数据库默认按数据源目录隔离并一表一文件；复杂数据库层级按需启用。数据资产目录为 `02-架构与契约/数据资产/`。

## 安全规则

- 目标目录已存在时不得覆盖，必须读取现有知识库并进入更新流程。
- 初始化前必须展示目录、已发现事实、假设和待确认项。
- 初始化可按当前宿主 Agent 创建或补充一个入口文件：Codex、Qoder、Trae 为 `AGENTS.md`，Claude Code 为 `CLAUDE.md`。该文件必须在 Proposal 中明确，且只能写入 Context Atlas 受管区块；已有文件的其他内容必须保留。无法识别宿主时不得创建入口文件。
- 初始化结果必须自包含，不得引用模板仓库中的私有相对路径。

## 技术栈

初始化不接收技术栈选择参数。Agent 扫描项目后，将 Java、Python、前端及其他技术记录到同一份技术栈知识中；技术数量不改变知识库目录、Schema 或检查器。

## 工作区配置

- 初始化 Proposal 可选 `workspace_profile`，仅允许 `standard` 或 `obsidian`，缺省为 `standard`。
- `standard` 不创建 `.obsidian/`；`obsidian` 创建最小 `app.json` 和预置类型颜色组的 `graph.json`。
- `.obsidian/` 只保存本地展示配置，不属于正式知识；验证器和所有知识读取操作必须忽略它。
- 初始化不得覆盖已有目标或已有 Obsidian 配置。
