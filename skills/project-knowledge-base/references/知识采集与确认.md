# 知识采集与确认

## Source types

Use only these types: `user_statement`, `repository_file`, `command_output`, `existing_document`, `external_document`, `ai_inference`. Give every formal knowledge item at least one registered source ID.

Repository observations are evidence, not user approval. AI inference remains `proposed`; never convert it to an approved fact because it looks plausible.

## Proposal contract

Present the following before a formal write:

| Field | Required content |
| --- | --- |
| Target | Exact files and IDs to create or change |
| Facts | Values and source IDs |
| Inferences | Explicit `ai_inference` items |
| Unknowns | Missing information and how the Agent tried to find it |
| Conflicts | Competing values, source IDs, and required resolver |
| Profiles | Additions and new knowledge gaps, or `none` |
| Validation | Commands and expected structural checks |

Accept only an explicit user confirmation referring to the current Proposal. If facts or targets change afterward, present a revised Proposal and confirm again.

## Stored states

- `missing`: required knowledge is absent.
- `proposed`: sourced candidate, not approved.
- `approved`: include `approved_by`, `approved_at`, semantic `version`, and `sources`.
- `conflicted`: preserve at least two distinct sources and `resolution_required_from`.
- `stale`: evidence may no longer describe the current project.
- `superseded`: retained old version with a valid `superseded_by` link.
- `archived`: historical context, never current authority.

When explaining a knowledge base, label confirmed facts, approved decisions, open decisions, excluded scope, and evidence gaps separately.
