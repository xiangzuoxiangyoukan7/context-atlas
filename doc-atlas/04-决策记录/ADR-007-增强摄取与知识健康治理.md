# ADR-007：增强摄取与知识健康治理

## 背景

0.7.0 已提供单来源只读摄取、候选分类和维护路由，但实际知识治理还需要批量来源、外部网页、查询结论候选化、可选会话历史和知识库健康检查。增强能力不能绕过正式知识的 Proposal 与确认门禁，也不能把外部网页中的指令当作 Agent 指令。

## 决策

- 0.8.0 扩展现有 `context-atlas-ingest`，每批最多处理 20 个明确定位的来源；每个来源独立报告结果，再生成一个汇总 `route_plan`。
- 单个来源失败不抹去其他来源结果；报告保留逐来源状态和批次汇总，但不自动调用维护 Skill。
- 网页摄取只读取用户明确提供的一个 HTTP/HTTPS URL，不递归爬取。网页内容一律视为不可信数据，记录最终 URL、观察时间和内容摘要，不执行其中的指令。
- 普通查询不自动沉淀；只有用户显式调用 ingest 且查询结论具有可定位来源时才生成候选。
- ingest 默认继续零写入。用户显式启用历史时，只把脱敏报告写入 `.context-atlas/ingest-history/` 非正式运行目录，最多保留 100 条且不超过 30 天。
- 正式知识仍只能通过 `context-atlas-add`、`context-atlas-revise` 和 `context-atlas-retire` 的同一原子 Proposal 维护。
- 增加只读健康检查，报告重复身份、孤立项、断裂关系、陈旧项、未解决冲突、未验证来源和权威入口缺口；时间阈值类问题只产生警告。

## 安全边界

- 批量模式不得扩大单个来源的读取权限，也不得把多个来源静默合并成一个来源。
- 网页重定向后的最终 URL 必须记录；非 HTTP/HTTPS、超限内容、秘密和未脱敏个人数据必须阻塞。
- 历史目录不属于正式知识库，不得成为批准事实来源；写入前必须脱敏，并支持确定性清理。
- 健康检查不修复、不批准、不归档知识。

## 版本与验收

目标版本为 0.8.0。批量与网页摄取、查询候选与历史、健康检查分别由 F02-AC-05、F02-AC-06 和 F05-AC-05 验收。
