# ADR-001：核心模型与技术栈扩展

## 背景

多个项目需要共享知识表达和验收治理，但 frontend、Java、Python 的构建和测试约束不同。

## 决策

核心知识模型、状态流转、权威来源、验收结果和证据规则统一；技术栈差异通过 profile 以加法方式表达。profile 不得覆盖核心规则。

## 影响

模板可以跨项目复制，检查器可以统一运行，profile 可以独立演进；项目必须显式选择 profile，不能仅由源代码自动推断。

## 回滚条件

若某技术栈无法用加法约束表达，先新增独立 profile 版本并保留核心模型，不直接修改既有核心字段。
