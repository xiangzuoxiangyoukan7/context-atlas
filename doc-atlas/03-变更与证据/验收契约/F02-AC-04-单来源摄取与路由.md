# F02-AC-04：单来源摄取与维护路由

## 前置条件

- Agent 已安装当前 Context Atlas 插件并能读取一个目标项目及其知识库。
- 测试来源具有稳定定位；敏感输入场景使用虚构测试值，不使用真实秘密或个人数据。

## WHEN

- 用户显式调用 `context-atlas-ingest` 并提供一个主来源；或测试规定的多来源、冲突、推断、敏感内容、缺失知识库和不兼容格式场景。

## THEN

1. 单个仓库文件产生 `add`、`revise` 或 `ignore` 候选以及可解释的 `route_plan`，且零写入。
2. 同一来源同时产生 `add` 和 `revise` 时输出一个复合 `route_plan`，不调用维护 Skill。
3. 多个独立来源输入时返回 `blocked` 并要求拆分。
4. 与批准事实冲突时输出 `conflict`，保留双方来源，不自动选择。
5. `ai_inference` 不能成为主来源或批准事实。
6. 来源含秘密或未脱敏个人数据时返回 `blocked`，报告不回显敏感值。
7. 知识库缺失或格式不兼容时分别只路由 `context-atlas-init` 或 `context-atlas-upgrade`。
8. 自然语言未显式调用 ingest 时不触发该 Skill；显式 ingest 仍保持只读。
9. Codex 与 Claude 安装形态均能发现该 Skill，并对规定场景输出一致的核心字段、`writes_performed: false` 和 `confirmation_state: not_applicable`。

## 验证方式

- 单元测试验证 Skill 契约、单来源和阻塞分支、报告字段与零写入边界。
- 构建测试验证两个平台安装形态包含同一 Skill、引用和必要运行资产。
- 跨 Agent 场景验证核心报告字段、路由结果和文件差异，不把模型措辞逐字一致作为通过条件。
- 实际结果与证据在实现后另行记录；本契约批准不预填通过状态。
