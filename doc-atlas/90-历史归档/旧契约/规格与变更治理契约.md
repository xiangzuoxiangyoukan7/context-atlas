# CONTRACT-SPEC-001：规格事实基线与变更治理契约

## 目的

使项目需求、功能、设计和验收达到开发者与 AI 可共同理解、可追溯、可检查的规格强度，同时保持 Context Atlas 的知识治理边界，不将外部 SDD 工具变成第二套正式事实源。

## 信息分层

| 层次 | 回答的问题 | 当前权威 |
| --- | --- | --- |
| 需求与功能规格 | 做什么、为谁做、为什么做、可观察行为是什么 | Context Atlas 当前事实基线 |
| 架构、设计与契约 | 在已批准约束下如何实现 | Context Atlas 稳定契约或变更工作区 Design |
| 外部任务 | 本次实现修改哪些位置、按什么顺序执行 | OpenSpec、Spec Kit、Issue 或其他任务系统 |
| 需求与功能中的验收标准和场景 | 实现前如何判断行为正确 | Context Atlas |
| 验收结果与证据 | 实际执行了什么、结果和版本是什么 | Context Atlas 证据层 |

下层可以引用上层，不得通过复制形成独立权威。代码、任务完成状态、测试结果或外部归档动作均不得自动批准项目事实。

## 当前基线与变更工作区

Context Atlas 保存当前批准且有效的事实。单次变化在独立变更工作区表达为 Proposal、规格 Delta、可选 Design、外部 Tasks 引用和 Acceptance Plan。每个变更应具有一个可用一句话表达的意图；能够独立批准、交付或回滚的无关能力应拆分。

变更推荐经过 `draft -> clarifying -> proposed -> approved -> implementing -> verifying -> accepted -> merged -> archived`；`rejected`、`cancelled` 和 `superseded` 为终止或替代状态。该状态只描述变更生命周期，不构成任务执行许可。

## 规格 Delta

- `ADDED`：新增不存在的规范行为或能力。
- `MODIFIED`：修改既有行为，必须携带目标规范的完整新内容，不能只保存局部片段。
- `REMOVED`：取消行为，必须记录原因、替代项、迁移方式、兼容期限、影响和回滚方式。
- `RENAMED`：仅改变稳定名称或标识映射，不改变行为。
- `SUPERSEDED`：新知识取代仍有审计价值的旧知识，必须建立双向替代关系并迁移当前引用。

变更被接受后，Delta 只生成 Context Atlas 基线合并 Proposal；只有精确修订确认后，对应 `add`、`revise` 或 `retire` 流程才能修改当前事实。

## 规格就绪度

批准状态、生命周期和规格就绪度相互独立。进入实现前至少满足：范围与非范围明确；规范性行为可观察；输入、输出、失败和重要边界已描述；关键非功能约束可验证；每项行为存在验收场景；不存在会改变规格、设计或任务拆分的阻塞问题。

阻塞问题使用稳定 ID，并记录问题、影响范围和状态。无法自动判断的清晰性、合理性或业务覆盖问题标记为 `review_required`，不得被自动检查器判为已经解决。

## 验收分层

- 需求在实现前定义业务验收标准；功能以内嵌稳定场景编号定义对象、前置条件、触发、预期结果、边界和验证方式。
- 验收结果记录 `not_started`、`partial`、`passed` 或 `not_applicable`。
- 验收证据记录命令或步骤、环境、实际输出、版本和可访问位置。

验收矩阵汇总内嵌场景、结果和证据。证据通过只证明对应场景得到覆盖，不能替代责任人对业务结论的确认。格式 8 及更早版本的独立验收契约继续可读，但格式 9 不再默认创建。

## 外部 SDD 适配

OpenSpec 的 `proposal/specs/design/tasks` 分别映射为变更提案、规格 Delta、变更设计和外部任务引用。Spec Kit 的用户场景、功能要求、成功标准、计划、契约、数据模型、任务和 Checklist 映射为相应知识候选或审查证据。适配器默认只读，必须保留来源仓库、提交或版本以及原始路径。

实现顺序为 OpenSpec 适配优先、Spec Kit 适配随后。适配结果先生成差异和 Proposal，不直接复制外部目录，也不把外部 `archive`、任务勾选或分支合并解释为 Context Atlas 批准。

## 检查与审查

确定性检查器按语法、引用、规格、覆盖和一致性分层；规则必须来自 Schema、关系目录和受控操作定义。只读 `context-atlas-review` Skill 负责需求、功能、设计、变更以及实现或验收就绪度审查，输出问题和候选结论，不正式写入知识库。
