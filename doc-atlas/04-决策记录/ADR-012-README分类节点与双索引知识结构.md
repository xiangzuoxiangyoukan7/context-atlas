# ADR-012：README 分类节点与双索引知识结构

## 背景

能力地图、验收矩阵和目录 README 同时汇总知识，会导致新增知识时重复维护。仅依赖目录又无法在 Obsidian 图谱中清晰表达知识分类。格式 10 已取消独立契约与验收契约，但物理目录和兼容文档仍保留旧命名与遗留结构。

## 决策

- 知识库同时提供目录树和知识图谱两种索引。
- 每个知识目录的 `README.md` 是具有稳定 `IDX-*` 身份的 `knowledge_index` 分类节点。
- 每个现行知识项使用唯一 `rel_classified_under` 指向主要分类；README 只维护到上级分类的正向关系，成员通过反向索引获得。
- 文件系统表达物理归属，其他 `rel_*` 表达需求、实现、调用、数据、验证和替代等业务语义。
- 取消人工能力地图、验收矩阵、当前变更和关系目录；对应视图从现行知识动态生成。
- 正式知识目录不保存 `TEMPLATE.md`；知识项模板集中在 `.project-kb/templates/knowledge/`。
- `02-架构与契约/` 更名为 `02-技术基线/`，因为当前模型不再包含独立契约类型。
- 格式 11 是当前结构。新建与升级结果必须使用同一套物理结构、Schema、关系和运行资产。
- 旧契约能唯一归入需求、功能或具体技术对象时才迁移；归属不明确时升级阻塞并保持原知识库不变。
- 升级成功后不得残留旧目录、人工汇总文件、正式目录模板或独立契约类型。

## 影响

- `children` 继续提供目录渐进读取；`neighbors` 和 bounded graph 提供分类与业务图谱读取。
- Obsidian Backlinks 和 Graph View 可以直接显示分类成员，但 Obsidian 不是格式权威或运行依赖。
- 初始化器、升级器、检查器、模板、Schema、示例、测试及三平台资产必须同步到格式 11。
- 旧格式兼容资产只服务升级诊断和转换，不成为升级后知识库的现行类型。
