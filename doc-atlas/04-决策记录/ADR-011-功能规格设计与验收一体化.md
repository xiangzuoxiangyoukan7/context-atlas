# ADR-011：功能规格设计与验收一体化

## 背景

将功能行为、功能设计、独立契约和验收契约拆成多份文件，会迫使开发者与 Agent 在多个知识节点之间反复跳转，同一规则也容易重复维护。项目责任人要求功能文档同时回答做什么、如何设计和如何验收，并取消独立契约与验收契约知识类型。

## 决策

- 需求记录业务目标、业务规则、范围、成功指标和业务级验收标准。
- 功能统一记录规范性行为、完整功能设计和稳定编号的内嵌验收场景，成为开发、排查和验收的主要入口。
- 功能设计至少覆盖总体方案、处理流程、输入输出与状态变化、关键规则、异常边界、安全与非功能设计、关联技术对象和设计取舍。
- 功能自身的设计和局部约束不得拆成独立设计文档或独立契约。
- 模块、具体接口、数据库、数据资产和外部依赖等可复用技术对象继续独立建模；功能必须说明它们如何共同完成功能，并通过 `rel_*` 关系连接详细定义。
- 不再维护 `contract`、`independent_contract` 和 `acceptance_contract` 当前知识类型。验收结果、验收矩阵和验收证据继续独立维护并关联功能内嵌的 `AC-*` 场景。
- 新建知识库使用格式 10。格式 1 至 9 保持可读；旧契约归属不明确时升级必须阻塞，不能由格式转换器猜测业务归属或改写批准状态。
- 本轮保留 `02-架构与契约/` 物理路径，目录重命名另行决策。

## 替代关系

- 本决策替代 ADR-010 中允许独立契约继续建档的部分；ADR-010 关于具体接口粒度和验收场景内嵌功能的其余决策继续有效。
- 本决策替代 ADR-005 中将功能自身设计、契约和验收契约作为独立规格层的部分；其变更工作区和外部 SDD 权威边界继续有效。

## 影响

- 功能模板和就绪度检查增加强制设计章节。
- 新模板、Schema Catalog、初始化结构和关系目录移除两类契约。
- 当前契约内容在保持稳定行为与验收编号的前提下回归 F01 至 F05，旧文件进入历史归档。
- 历史验收结果不因表达结构变化而重新标记为通过。

## 回滚条件

若多个真实项目证明单功能文档因设计与场景规模无法维护，可以评估功能附属分册，但附属分册仍归属于同一功能，不恢复通用独立契约或逐场景独立文件。
