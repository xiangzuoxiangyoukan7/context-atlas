# 项目目标与成功标准

## 背景

AI Agent 在不同项目中需要反复理解目标、边界、设计和验收标准。缺少统一知识入口时，AI 容易使用过期文档、把推测当事实，或生成缺乏依据的执行计划。

## 项目目标

提供一套供 AI Agent 使用的项目知识库系统，使用户可以在 Codex、ChatGPT、Claude Code 等 Agent 中完成知识库初始化、知识采集、确认、维护和使用。正式知识写入由平台固定操作符触发；自然语言用于调研、补充需求和确认内容，不能单独触发正式写入。

## 产品形态

本项目第一阶段交付：

1. 工具无关的知识模型和 AI 知识采集协议。
2. 可安装的项目知识库 Skill，作为 Agent 的主要使用入口。
3. 完整、可直接实例化的通用知识库模板。
4. 同一知识库内记录任意数量技术栈的通用技术栈知识模型。
5. 单技术栈与多技术栈两套同结构完整样例。
6. 由 Schema 驱动的确定性结构和追溯检查器。

用户不需要学习独立知识库 CLI。Agent 负责调研、提问和组织候选知识；项目责任人负责确认；知识库负责确定性存储、版本、关联和校验。

## 成功标准

- Agent 能在项目根目录生成 `doc-<项目目录名>/`，且目标存在时不会覆盖。
- 初始化产物完整、自包含，不依赖模板仓库的相对文件。
- 初始化不要求选择技术栈；Java、Python、前端及未来技术均记录在同一知识库中。
- 知识库明确区分代码事实、用户陈述、外部资料和 AI 推测。
- 用户确认前，候选知识不得成为批准基线。
- 项目目标、功能、架构、契约、数据库、原型、外部依赖、任务、ADR、验收和证据均可版本化和追溯。
- 检查器实际读取 Schema，并发现结构、状态、链接、版本和追溯错误。
- 至少两种 Agent 按同一协议生成的知识库都能通过一致性检查。
- 本项目自身使用同一规范维护 `doc-atlas/`。
