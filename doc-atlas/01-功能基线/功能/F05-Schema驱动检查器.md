# F05：Schema 驱动的确定性检查器

## 目标

检查器实际读取 Schema，对知识库结构、状态、版本、链接和追溯关系进行确定性校验。

## 包含

- 元数据、枚举、ID 和状态流转。
- 文档链接和跨知识类型引用。
- 技术栈记录的结构与追溯约束。
- 功能、设计、任务、验收和证据闭环。
- 数据库、原型、外部依赖引用。
- `data_asset` Schema 和数据来源类型列表校验。
- 批准来源、版本、冲突和敏感信息风险。
- 批准状态、生命周期状态和规格就绪度的独立约束。
- 规范性行为与验收场景覆盖、阻塞问题与就绪度一致性。
- `ADDED`、`MODIFIED`、`REMOVED`、`RENAMED` 和 `SUPERSEDED` 变更增量的目标、完整性、迁移与引用约束。
- 需求、功能、契约、外部任务引用和验收证据之间的跨文档一致性。
- 重复身份、孤立项、断裂关系、陈旧项、未解决冲突、未验证来源和权威入口缺口的只读健康报告。

## 检查层次

检查器按语法、引用、规格、覆盖和一致性分层报告。机器可确定的问题使用错误；需要业务或架构判断的问题使用 `review_required`，不得由检查器自动批准内容。语义清晰度审查由只读审查能力提供候选结论，确定性检查器只实施可稳定判定的规则。

## 验收

- `F05-AC-01`：检查器以 Schema 为唯一结构规则来源，不维护不一致的硬编码副本。
- `F05-AC-02`：有效样例通过，规定的结构、追溯、冲突和安全反例失败并提供定位信息。
- `F05-AC-03`：检查器能识别行为缺少验收覆盖、阻塞问题与就绪度矛盾、非法或不完整 Delta，并区分确定性错误与人工复核项。
- `F05-AC-04`：检查器能验证需求到功能、契约、外部任务引用和验收证据的追溯覆盖，且不会把外部任务状态或归档动作当成正式知识批准。
- `F05-AC-05`：健康检查能稳定定位结构问题和人工复核项，且运行前后正式知识摘要不变。
