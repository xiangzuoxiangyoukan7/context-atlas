# AI 协作规则

## 读取顺序

每个新会话按以下顺序读取：

1. 当前 Agent 已安装的项目知识库 Skill；不支持 Skill 时读取通用协议文档。
2. 项目根 `README.md`。
3. `doc-<项目名>/README.md`。
4. 本文件和 [AI 知识采集协议](./AI知识采集协议.md)。
5. 与用户请求直接相关的需求、包含设计、关键决策与验收场景的功能、架构、具体技术对象和验收证据。
6. 存在关联变更、验收证据或外部任务引用时按需读取；它们提供知识变化上下文，不构成执行许可。

目标项目可以存在 `AGENTS.md`、`CLAUDE.md` 等入口。初始化时由当前宿主 Agent 选择对应文件：Codex、Qoder、Trae 使用 `AGENTS.md`，Claude Code 使用 `CLAUDE.md`。文件不存在时可在已确认 Proposal 中创建，文件存在时只能追加或更新 Context Atlas 受管区块，必须保留项目原有内容；无法识别宿主时不得自动创建。

## 上下文规则

- 需求、包含设计与关键决策的功能、具体技术对象和验收证据是不同类型的证据，不能互相替代。
- 决策背景、备选方案、当前选择、影响、回滚条件和来源归入其负责的需求、功能、技术对象或治理文档，不建立独立决策知识类型。
- 发现冲突时列出冲突来源、版本和需要确认的问题，不自行选择“看起来合理”的内容。
- 缺少范围、边界、依赖或验收标准时先提出问题，不补写未批准事实。
- 仓库观察、用户陈述和 AI 推测必须分别标记；AI 推测只能作为待确认假设。
- 写入正式基线前先向用户展示 Proposal、来源、假设和未决问题。
- 历史归档只能提供背景，不得作为当前需求或完成状态来源。
- 正式知识归档必须先完成替代关系和当前引用迁移，再提交包含路径、摘要、原因与时间的 Proposal；精确修订号确认后才能移动，失败必须回滚。
- 自动检查通过只表示结构和引用满足规则，不表示内容已经正确批准。
- 生成计划时必须列出每项计划步骤引用的功能内设计、具体技术对象和验收依据。
- 本 Skill 不执行代码、不替用户验收、不把 AI 输出当成项目事实。

## 初始化与维护

- 初始化默认在项目根目录创建 `doc-<当前目录名>/`。
- 目标知识库已存在时不得重新初始化或覆盖，应进入更新流程。
- 初始化和更新均由 Agent 与用户对话驱动，不依赖独立用户 CLI。
- 结构检查器只验证格式和追溯关系，不能批准内容。

## 升级完整性门禁

- `format_version` 只证明知识库使用的表达格式，不证明目录、字段、关系、权威入口或健康状态已经是当前最新版本。
- 每次插件升级都必须使用当前安装插件的兼容清单和 Schema 执行完整只读诊断：版本可读性、最新目录结构、废弃目录/文件/模板、旧路径引用、Front Matter 字段、唯一分类关系、authority 目标、链接、Schema、关系目录、健康检查和 children/neighbors/有界 graph 冒烟验证。
- 当前格式如果仍有任何确定性问题，诊断不得返回“无需升级”；必须生成同格式结构归一化 Proposal，且该 Proposal 可重复执行、原子应用并在应用后重新验证。
- 无法安全判断业务归属的旧知识不得丢弃、不得留在废弃类型或目录中、不得因此阻断整体升级；应转换为最新格式的 `knowledge_item`，保留正文、来源和稳定 ID，标记 `missing` 或放入待确认知识入口。
- 升级不得改变 `project_version`、批准状态、业务含义、来源事实或历史；删除仅限已证明为废弃模板/汇总文件，真实知识必须迁移并保留可追溯性。
- 只有“版本兼容且完整结构检查通过”才能报告“无需升级”；只要验证未运行或验证失败，下一步必须是生成/应用升级提案或报告明确阻塞项。

## 任务调度边界

Context Atlas 不决定用户或其他插件能否执行任务。任务可以来自用户、Superpowers、OpenSpec、Issue 系统或其他 Agent；知识库只负责提供相关事实、约束、影响和证据。正式知识写入仍必须遵守 Proposal、显式确认、来源和验证规则。
