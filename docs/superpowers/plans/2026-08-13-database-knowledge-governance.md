# 数据库知识治理实现计划

**目标：** 落地多数据源、数据库单元、可选命名空间和一表一文件模型，确定性检查字段含义、值域、物理外键记录和逻辑外键字段链接。

**架构：** JSON Schema 约束四类数据库实体的顶层元数据；`database.py` 解析数据表正文中的字段表和主子表映射；统一关系索引验证 `rel_belongs_to`、`rel_reads`、`rel_writes` 和 `rel_logical_parent`。数据库文档只保存基础知识和子表到主表的正向关系，不反向保存业务消费者。

**约束：** 全部 Python 代码使用中文文档字符串、类型标注和关键逻辑注释；数据库凭据只记录配置位置或环境变量名，不保存值；已有物理外键如实记录但不要求新增；每个任务先写失败测试、再最小实现、全量验证、独立提交。

## Task 1：数据库实体 Schema 与层级关系

- 创建 `data-source.schema.json`、`database-unit.schema.json`、`database-namespace.schema.json`、`database-table.schema.json`。
- 新增 `rel_belongs_to`，允许 `DB -> DS`、`NS -> DB`、`TABLE -> DB/NS`。
- 验证 Oracle、PostgreSQL、KingbaseES、MySQL 的产品枚举及命名空间可选边界。
- 测试后提交：`规范：建立数据库实体与层级关系`。

## Task 2：字段含义和值域检查器

- 创建 `scripts/project_kb/database.py` 并接入总验证器。
- 表文档必须包含“字段定义”表；每行包含字段编号、字段名、类型、可空、默认值、中文含义、值域类型、允许值或最小值、最大值或格式、是否允许其他值、约束执行位置、来源和块锚点。
- 值域类型只允许 `enum`、`range`、`format`、`any`、`unknown`；按类型检查必要单元格。
- 精确错误码覆盖字段缺失、重复、值域缺失、枚举格式、范围、锚点和来源。
- 测试后提交：`检查：验证数据库字段和值域`。

## Task 3：物理外键与逻辑外键字段映射

- 解析“主子表关系”表，校验子字段存在、主字段链接有效、`rel_logical_parent` 同时存在。
- `物理约束=是` 时必须记录真实约束名；`否` 时保留逻辑外键，不要求数据库创建约束。
- 主字段使用 `[[主表文件#^FIELD-ID|FIELD-ID]]` 精确链接；统一关系解析器支持表格行末块锚点。
- 测试后提交：`检查：验证逻辑外键字段映射`。

## Task 4：模板、Skill 与数据库产品样例

- 建立数据源、数据库单元、命名空间、数据表模板和中文关系说明。
- Skill 说明 Oracle、KingbaseES、PostgreSQL、MySQL 的实际层级映射，以及字段值域和外键填写方法。
- 黄金样例至少包含 PostgreSQL 数据源、数据库、Schema、主表与子表；功能从使用方引用表。
- 初始化产物、两套样例和 Skill 内置资产保持一致。
- 测试后提交：`文档：落地数据库知识治理规范`。

- 运行全量测试、注释、规则覆盖、Skill 同步、三套知识库检查、代表性表影响分析和 `git diff --check`。
- 记录脱敏命令、退出码和字段/逻辑外键检查结果。
- 提交：`验收：完成数据库知识治理阶段`。
