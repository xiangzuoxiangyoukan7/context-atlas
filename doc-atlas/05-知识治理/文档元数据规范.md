# 文档元数据规范

核心字段和枚举以 `schemas/` 为唯一机器规范。检查器必须读取 Schema，不得维护会独立漂移的规则副本。所有功能和任务验收声明必须非空、唯一，并在验收矩阵中恰好出现一次。

## 正式知识项

正式知识项至少包含 `id`、`type`、`title`、`status`、`version`、`sources` 和 `last_updated`。批准内容还必须记录 `approved_by` 和 `approved_at`。

知识状态为 `missing`、`proposed`、`approved`、`conflicted`、`stale`、`superseded`、`archived`。功能状态、任务状态和验收结果属于不同状态域，不得混用。

## 核心验收结果

`not_started`、`partial`、`passed`、`not_applicable`。`passed` 必须有可定位证据和对应版本；`failed`、`blocked` 是任务或证据状态，不是验收结果枚举。

## 来源与确认

来源必须属于 `user_statement`、`repository_file`、`command_output`、`existing_document`、`external_document` 或 `ai_inference`。AI 推测必须单独标记并等待项目责任人确认。

## 技术栈规则

技术栈记录可以包含 `version`、`framework`、`package_manager`、模块目录和运行命令等字段，但不能替换核心字段、删除核心验收项或改变权威来源顺序。
