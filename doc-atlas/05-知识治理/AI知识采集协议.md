# AI 知识采集协议

## 定位

本文档记录 Context Atlas 项目自身在知识采集时使用的协作语义。插件的完整、平台无关执行规则以 [知识采集与确认](../../references/知识采集与确认.md) 及其引用的状态机为唯一规范源。Skill 负责加载和编排该协议，不另行复制一份完整规则。

## 职责

- **产品协议**：定义 Proposal、确认、冲突、状态转换、主动采集和报告规则。
- **Skill**：定义触发条件、必读协议、执行入口和终止条件。
- **目标知识库说明**：保留自包含的持久化治理语义，并在无 Skill 时提供最低兼容入口。
- **Schema**：定义文档结构、字段和状态的机器权威。
- **执行器与检查器**：确定性实施确认门禁、受控写入和结构验证，不批准内容。
- **项目责任人**：确认目标、范围、设计、优先级和验收标准是否正确。

## 本项目的执行要求

1. 当前 Agent 先读取已安装的 Context Atlas Skill 和它指向的 `references/` 协议。
2. 调查仓库、配置和现有文档，将事实、用户陈述和 AI 推测分开。
3. 正式写入前展示当前 Proposal 的目标、事实、来源、推断、未知项、冲突、影响和验证方式。
4. 只有当用户明确确认当前修订时才进入正式写入；目标、事实、关系、影响或验证变化时重新确认。
5. 写入后运行当前知识库内置检查器，报告实际文件、确认状态、验证结果、未知项和冲突。

## 持久语义

- 每项正式知识必须内嵌可定位来源及其观察时间、确认状态；已确认来源还记录确认时间。独立来源实体只可用于旧格式迁移或公共去重，不能成为理解单项知识的前置条件；`ai_inference` 不得直接成为批准事实。
- 用户确认前，候选内容保持 `proposed`；沉默不是确认，Agent 不得将自己记为批准人。
- 冲突必须保留所有竞争值和来源，标记需要的裁决者，不自动选择“更新”或“更合理”的值。
- 替代批准知识时先建立双向关系并迁移当前引用；有审计价值的历史通过包含路径、摘要、原因和时间的已确认提案移动归档，执行失败必须回滚，归档不得覆盖当前知识。
- 密码、Token、私钥和未脱敏个人数据不得进入知识库。
- 检查通过只表示结构和引用满足规则，不表示内容已被正确批准。

## 产品边界

Context Atlas 只负责知识的采集、确认、沉淀、读取、关系、影响、版本、冲突和归档，不负责规定项目如何开发。项目命令如有沉淀价值，应当作技术栈或相关技术契约中的带来源事实，不生成独立“开发指南”。
